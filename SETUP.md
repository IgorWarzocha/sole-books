## Phases

- [ ] **1. Establish a safe home.** Confirm this is a personal working branch created from `US-experimental`. Verify every GitHub fetch and push destination is private using authenticated repository visibility data, following `AGENTS.md`. A branch in a public repository is not private. Stop if a remote is public or cannot be verified. If there is no remote, setup can remain local. Never add personal details to `US-experimental`, `uk` or `demo`. Read `AGENTS.md`, `state.md`, `todo.md` and `.agent/skills/us-bookkeeping/SKILL.md`, including its setup references. Explain that this is an AI-researched experimental starting point, not professionally reviewed US tax software. Confirm the user's circumstances fit before promising coverage.

- [ ] **2. Gather the basics.** Ask in a short conversational batch for legal and trading names, business address and contact details, work sold, trading start, US tax residency and entity type, business time zone, and the first year or date to cover. Ask which states and localities they operate in and sell into. Find out what already holds their books, invoices, payments and evidence, what they want imported, and which tools they want to keep using. Ask only for information not already established. Do not request SSNs, EINs, W-9s, passwords or sensitive banking instructions in chat or this repo.

- [ ] **3. Resolve the recording requirements.** Follow the federal and state setup references in the bookkeeping skill. Research missing public requirements through current IRS, state revenue and local authority sources, using the user's actual activity and locations. Establish residency and entity scope, cash basis, calendar year and USD, filing and estimated-payment review, registration and DBA requirements, service taxability, nexus, permits, invoice requirements, contractor reporting and evidence retention. Record dated sources and decisions in `state.md`. Ask for private facts or professional review where public research cannot decide. If circumstances exceed the supported scope, agree a compatible external workflow or a narrower role for this repo. Do not mark unresolved legal or tax treatment as settled.

- [ ] **4. Agree imports and tool boundaries.** Offer files, exports, existing MCP connections or manual records according to what the user actually has. Inspect available capabilities before promising an integration. Agree each source, accounts, coverage dates, cutover date and which system owns each record, including whether this repo replaces or complements another tool. Use read-only access where possible. Ask before connecting services, granting access, installing integration tooling or writing to another system. Keep credentials in the tool's secure mechanism. Review field mappings and a small sample before bulk import. Record currency, gross receipts, fees, refunds, sales tax, invoice identifiers, time zones and duplicate detection. Reconcile overlapping sources rather than adding bank deposits and processor receipts twice. Record the supported repeat-import or manual refresh process. Do not invent a connector or leave a selected import silently unfinished.

- [ ] **5. Populate and connect the records.** Fill `trader.csv` from confirmed details and set the real time zone. Create the agreed calendar-year folders from this edition's headers and align the default year with the agreed starting view. Import only evidenced records, retaining source references and reconciling totals and gaps. Keep personal tax payments and pass-through sales tax separate from business profit. Enter only reviewed deductions, including explicit zero where appropriate. Do not duplicate prior-year asset purchases to represent depreciation. Align invoices, document status, remaining gross projections, recurring costs and rate changes. Establish opening cash and tax-liability balances only from evidence. Replace template text in `state.md` with the user's confirmed scope, system ownership, import coverage, obligations and evidence workflow. Replace the starter `todo.md` with their actual next actions. If starting fresh, explicitly record that no history was imported and what opening balances remain unverified.

- [ ] **6. Verify and hand over.** Check imported records against source counts, totals, balances and coverage. Run `make check` for every populated year using `TAX_YEAR=YYYY`. Install dashboard dependencies if needed, start Glance with the documented localhost command and verify the agreed year, USD, identity, time zone and totals. Ensure the dashboard's date-based year selection has the required ledgers. Confirm that the user understands any incomplete reconciliation or external tax workflow. Record how to add receipts, reconcile, refresh imports and update linked tools in `state.md`, with ongoing actions in `todo.md`. Nothing is sent, filed or paid during setup without direct approval. Once every phase is ticked and setup blockers are resolved, preserve the durable decisions in those files and delete `SETUP.md`. Keep the conditional `AGENTS.md` trigger for future template updates.
